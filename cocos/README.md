# 一亩稻 · Cocos Creator 迁移工程

本工程从仓库当前 `index.html`（v6.11.01）迁移，使用 **Cocos Creator 3.8.8**。原网页保留，迁移后的代码以 `assets/scripts/` 为准。

游戏仍是纸色界面的文字经营游戏：种一季稻、处理人物和田间事件、验米、加工销售、查看年终账本，再把积累带到下一季。无需额外注册游戏账号。

## 打开与运行

1. 在 Cocos Dashboard 的「项目」中导入**本目录 `cocos/`**。不要导入仓库根目录。
2. 使用 Creator **3.8.8** 打开，等待资源导入。
3. 在资源管理器中打开 `assets/scenes/Main.scene`。
4. 点击编辑器顶部的预览按钮。推荐竖屏预览，浏览器和编辑器预览按窗口排版，内容最宽 520，字号保持不变；原生平台当前采用 420 × 820 的竖屏基准。
5. 首页的「下田」进入正式季节，「突发事件练习」进入独立练习。

场景的 `Game` 节点挂有 `GameBootstrap` 组件。界面由该入口运行时创建，不需要手动逐个拖拽按钮。

如果窗口标题显示 `Untitled`，当前是编辑器新建的空场景。先在左下角资源管理器的 `assets/scenes` 中双击 `Main`，确认层级管理器里出现 `Main → Game`，再点击顶部三角形预览按钮。编辑状态下画布为空是正常的，界面在运行时创建。

如果浏览器自动跳转失败，可以在预览运行后直接打开编辑器的实时预览地址。本机当前地址为 `http://localhost:7456/`，需要保持 Creator 开着；有多个工程时端口可能不同，以编辑器实际地址为准。

## 代码约定

- `ctx.S` 是当前季节状态；`ctx.screen` 是当前页面。原来分散在网页全局的变量都进入这一个上下文，便于追踪，也避免多个实例互相影响。
- `data` 中仍有根据状态生成文案的函数。人物故事存在大量条件分支，不强行改成静态 JSON，以保留原有内容和规则。
- 每个迁移模块提供 `register(ctx)` 和 `initialize(ctx)`。先注册所有函数，再按网页原顺序初始化数据；这样保留函数提前声明和跨章节引用的行为。
- 简略注释放在入口、平台接口、时间管理、绘图及模块函数处。旧网页的大段历史变更说明留在原文件，迁移版不重复堆积。
- 迁移内容的动态对象使用 `any`，因为原版状态和故事分支较多。平台接口、时钟、模板节点和引擎入口有明确类型；新增独立系统应优先定义类型，逐步收紧旧字段。

## 为什么仍能看到类似 HTML 的模板

`Screens.ts` 保留原界面的内容描述，以免重写时遗漏大量故事、提示和选项。它们被 `TemplateTree` 解析成数据树，再由 `NativeRenderer` 绘制为 **Cocos Node、Label、Graphics、Button、ScrollView**。

运行时没有真实网页 DOM，没有 WebView，也不执行模板中的 JavaScript。操作只允许「函数名 + 字面量参数」，由 `GameRuntime.invoke` 分发。矢量路径由 `Graphics` 绘制，音效使用本地 WAV，存档使用 Cocos 的 `sys.localStorage`。

这是一层针对本游戏的迁移适配，不是通用浏览器。原网页的 CSS 没有直接复制；移动端布局、按钮与滚动由引擎重新实现。矢量渐变使用代表色、椭圆弧使用线段近似，画面不保证与网页逐像素相同。若后续大改某个页面，可以直接用 Cocos 预制体替换其模板和绘制逻辑，玩法层无需一起重写。

## 存档与可选在线功能

沿用原版跨季存档规则：图鉴、成就、季数及已设计的继承项使用同一存档键保存。**本次没有新增任意时刻断点续玩或云存档。** 同一设备的后续版本应保持存档键和字段兼容。

网页与 Cocos 是不同的运行容器，旧浏览器存档不会自动迁入 App 或微信。换设备、清理数据后的同步，需要以后另做云存档。

`GameBootstrap.apiBaseUrl` 默认留空。原版的在线生事、推演、组牌、人物说话等请求在未配置服务时回退到作者内容，不阻塞正式游戏。仓库没有对应服务端，本次没有伪造这些服务，也不会向 `localhost` 请求。

接入已有服务时，在 `Main.scene` 的 `GameBootstrap` 组件填写实际 HTTPS 地址。微信发布时还需要在公众平台配置合法请求域名；App 也应检查网络和隐私配置。

## 检查与验证

在本目录执行：

```sh
npm --prefix tools ci
node tools/check.cjs
```

检查工具默认读取 Mac 上的 `/Applications/Cocos/Creator/3.8.8/CocosCreator.app` 的官方类型声明。如果安装位置不同，先设置 `COCOS_EDITOR` 为编辑器路径。

回归测试覆盖：

- 迁移版与原网页在相同随机种子、相同操作下的状态及页面模板一致性（仅移除移动端不用的键盘提示）。
- 年景卡、跨季卡、按钮的样式层级与富文本换行；第 4 季带入内容、图鉴与五种练习入口。
- 30 个随机开局完整走到年终结算。
- 五种练习不改变正式季节状态。
- 16 张水渠地图可以通过旋转接通。
- 正式事件的体力消耗、成功奖励、失败减产及单次结算。
- 进入后台后暂停计时，回到前台后继续。
- 跨实例读取持久化的季数。
- 操作分发拒绝任意脚本。

根目录原有的 `tests/canal.cjs` 仍用于网页版水渠规则检查。

`tools/migrate.cjs` 是一次性迁移工具，`tools/create-assets.cjs` 是初始资源生成工具。**日常开发不需要运行它们**：再次运行迁移工具会覆盖已拆分的内容模块；再次生成场景会重置入口组件参数。修改迁移版时直接维护 `assets/scripts`，通过检查工具验证。

## 发布微信小游戏与 App

在 Creator 中打开「项目 → 构建发布」，入口场景选 `Main`。

- **微信小游戏**：选择微信小游戏平台，填写自己的小游戏 AppID，构建后用微信开发者工具预览和真机调试，再按平台流程提交审核。本工程没有绑定他人的账号、AppID，也没有公开发布。

- **Web**：选择 Web Mobile，可继续提供浏览器游玩。

本次验证以本地逻辑回归、Creator 构建和本地运行为准。微信真机、Android/iOS 真机及平台审核必须在相应账号、设备和发布环境下另外验证，不能以网页预览替代。

### 预览退出时的生命周期修复

Creator 先销毁 Canvas 子树，再调用 GameBootstrap.onDestroy；旧的 NativeRenderer.dispose 重复读取已销毁 Canvas 的 children，导致 `parent.children is not iterable`。清理前使用 Cocos `isValid(node, true)` 排除已销毁或等待销毁的节点；dispose 可重复调用，销毁后不再同步界面或执行旧按钮回调。正常切页仍销毁旧节点。

`tools/test-lifecycle.cjs` 回归覆盖已销毁 Canvas、等待销毁 Canvas、重复清理、旧回调及正常节点清理。修改后若 Console 仍显示同一条旧记录，可以 Clear 后再启动和停止预览核对。

已在 Creator 3.8.8 内连续启动、停止两次预览，Console 的 Error 计数保持为 0；退出顺序回归测试和原版玩法对照通过，Web Mobile 构建已更新。

### 编辑器内嵌预览的监听器累积提示

`MaxListenersExceededWarning` 中的 `render-view-deleted` / `new-window` 与 Electron 的 `WebContents` 有关，项目没有注册这些事件。长时间反复使用内嵌预览时出现的这类提示需要与游戏脚本错误区分。当前采取规避方式：保存场景、重启 Creator 清理累积监听器，再将顶部预览方式改为“浏览器预览”。本机工程的预览配置已设为 `browser`。

保持 Creator 打开，可在浏览器直接访问 `http://localhost:7456/`；该地址运行的是 Cocos 工程，不是根目录的原版网页。浏览器刷新不会重复创建编辑器内嵌预览窗口。本处理没有增大监听器上限、屏蔽警告或修改已安装的编辑器文件，不能视为对编辑器内部缺陷的永久修补。
